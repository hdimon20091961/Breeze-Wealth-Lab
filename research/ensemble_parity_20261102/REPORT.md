# Сверка Breeze и эталонной стратегии «что если» — 02.11.2026

## Вывод

Причины расхождений воспроизведены численно. Эталон — исходная стратегия
`ген_на_TorchSharp_oll_indi_ансамбльGPT_mult_(что если).cs`.
Проверены все 4539 сети из шести пакетов TorchSharp / Jordan / Encog.
Сети и входные рыночные данные в каждом сравнении одни и те же.

При передаче в загрузчики моделей Breeze признаков, рассчитанных эталонным
исходником, бинарные прогнозы **каждой сети на каждом баре совпадают**.
Это подтверждено на двух длинах истории. Причина расхождения Str% — подготовка
признаков в Breeze, а не округление около 0,5 или неисправные модели.

## 1. Воспроизведение Str% за 125 баров

История эталона: 2262 бара, 2017-10-31 — 2026-10-30. База сравнения:
`Close[2026-10-30] − Close[2026-05-04] = 37,71`.
125 приращений цены начинаются после базового бара 2026-05-04.

| Пакет | Сетей | Эталон «что если» | Текущий код Breeze | Загрузчик Breeze с признаками эталона | Различий классификаций за всю историю |
|---|---:|---:|---:|---:|---:|
| Encog ZZ1 | 1200 | 93,878185% | 80,575220% | 93,878185% | 0 |
| Encog ZZ2 | 529 | 54,703325% | 51,466193% | 54,703325% | 0 |
| TorchSharp ZZ1 | 879 | 105,122498% | 102,333162% | 105,122498% | 0 |
| TorchSharp ZZ2 | 745 | 80,608806% | 75,976326% | 80,608806% | 0 |
| TorchSharp ZZ1_J | 600 | 83,187146% | 84,545988% | 83,187146% | 0 |
| TorchSharp ZZ2_J | 586 | 103,074119% | 101,625897% | 103,074119% | 0 |

Округление эталона до целых воспроизводит показанные пользователем
94, 55, 105, 81, 83 и 103. Округление текущего Breeze до десятых воспроизводит
80,6; 51,5; 102,3; 76,0; 84,5; 101,6.
Средние последние сырые прогнозы также совпали со снимками:
Encog ZZ1 — 0,4855592; Encog ZZ2 — 0,3256460;
TorchSharp ZZ2 — 0,4352198; TorchSharp ZZ2_J — 0,3737521.

Формула на одну модель:

`Str% = 100 × Σ(class[t−1] × (Close[t]−Close[t−1])) / (Close[last]−Close[last−125])`.

ИТОГО — среднее этого показателя по всем моделям пакета. Торговый режим
в эту формулу не входит. В текущем коде Breeze формула уже соответствует
эталону; различаются классификации, поступающие в неё.

## 2. Какие признаки рассчитаны иначе

| Параметр | Эталон «что если» | Breeze для Encog | Breeze для TorchSharp/Jordan |
|---|---:|---:|---:|
| Aroon Up / Down | 48 / 48 | 40 / 40 | 48 / 48 |
| CorrelationAngle | 48 | 28 | 48 |
| Hurst | 80 | 120 | 80 |
| EMA сглаживания Jocker | 20 | 3 | 20 |
| VWMA в marketBreadth | 125 | 64 | 64 |

Эталон задаёт эти периоды непосредственно в `PrecomputeBaseIndicators`
и `CalculateMarketBreadthBase`. В Breeze они берутся через `LoadParameters`.
В проверенных Encog INI и системном INI нужные `Param_X*` отсутствуют;
Breeze подставляет значения по умолчанию, не соответствующие эталону.
Для всех четырёх пакетов TorchSharp/Jordan остальные проверенные признаки
совпали; отличается только `marketBreadth` (VWMA 64 вместо 125).

Пример на последнем баре Encog: нормированный CorrelationAngle равен
**+0,578863** в эталоне и **−0,918293** в Breeze.
Это существенно разные входы одной и той же нейросети.
За последние 125 решений в Encog ZZ1 различались 25 919 бинарных ответов
из 150 000; в Encog ZZ2 — 11 535 из 66 125.

`inventory.json` содержит проверку параметров всех INI, без выборки отдельных файлов.

## 3. Ошибка универсального чтения Bench

Эталон: `Bench=?(-?\d+(?:\.\d+)?)`.
Текущий Breeze: `(?:^|_)Bench\s*=?\s*(-?\d+(?:\.\d+)?)`.

Оба читают `..._Bench800_...`, но текущий Breeze не читает
`N Leven-3 Bench=697 all=697 ...`: перед Bench стоит пробел.
Поэтому Bench стал NaN у **всех 1200 Encog ZZ1 и всех 529 Encog ZZ2**.
В результате в Breeze Encog распределяется по децилям по именам файлов,
а не по Bench. Это влияет на Profit децильного режима, но не на средний Str%.

Кроме того, эталон использует `List.Sort` только по Bench, а Breeze —
`OrderBy(Bench).ThenBy(FileName)`. При равных Bench это может дать другой
состав децилей. Для точного воспроизведения нужен тот же порядок загрузки,
тот же компаратор и то же распределение по десяти группам.

## 4. Торговые режимы сейчас не соответствуют друг другу

Это вывод из исполняемых ветвей `Execute`, а не из подписи на интерфейсе:

| Реализация | Выбор | Целевая позиция |
|---|---|---|
| «что если» | Режим 0 | `Round(10 × доля положительных моделей, AwayFromZero)`; 0…10 |
| «что если» | Режим 1 | Число децилей со значением >= 50%; 0…10 |
| Breeze | Ensembles снят | Число децилей >= 50%; 0…10 |
| Breeze | Ensembles установлен | 10 при ансамбле >= 50%, иначе 0 |

Последняя строка — третий алгоритм. В этой эталонной стратегии он отсутствует.
На снимках с режимом 1 показываются результаты децильной торговли.
Для точного сопоставления режим 1 нужно сравнивать с децилями,
а режим 0 — с пропорциональной позицией, воспроизведённой по эталону.
Перестановка двух подписей не исправит отсутствующий алгоритм.

## 5. Profit и границы доказанного результата

Profit внизу Wealth-Lab — прибыль в процентах от начального капитала 3000,
а не отношение прибыли стратегии к прибыли benchmark.
Str% в отладочном отчёте — другая метрика: отношение среднего движения цены,
захваченного отдельными моделями за 125 баров, к движению SPY за эти бары.

## 7. Как выполнен аудит

- `prepare.py` создаёт локальные копии двух исходников. Меняются только
  получение внешних историй и вывод диагностических сообщений. Формулы,
  загрузчики сетей и классификация остаются исходными.
- `Initialize` стратегии не запускается: записи в торговые пакеты и
  экспортные ensemblePR не происходят.
- SPY берётся из `D:/fear_greed_close/Breeze/SPY.csv`; внешние символы — из
  локальных WealthData QX и исходных CSV сентимента. Обе реализации получают
  одинаковый календарь. Для пяти дат сентимента использовано последнее
  предшествующее наблюдение; это одинаково для обеих сторон.
- Признаки эталона формируются реальными `PrecomputeBaseIndicators` и
  `BuildFeatureMapFromCache`; Encog дополнительно использует свои веса признаков.
- Реальные модели .eg, .pt и .jbin выполняются загрузчиками обоих исходников.
- Контрольный вариант оставляет загрузчик Breeze и подставляет карту признаков
  эталона. Проверяется каждая бинарная классификация на всей истории.
- Сборка стенда завершилась без ошибок и предупреждений. JSON сохраняет
  результаты без округления; CSV содержит результаты каждой модели.
- Три пакета TorchSharp4GPU в этот сравнительный тест не включены:
  они не являются шестью пакетами данной эталонной стратегии.

CSV соответствует последнему запуску; итоговые JSON отдельно сохраняют обе длины истории.

## 8. Направление исправления

1. Зафиксировать совместимость legacy TorchSharp/Jordan/Encog с подготовкой
   признаков «что если». Новые GPU-пакеты сохраняют свой контракт параметров.
2. Восстановить универсальное чтение Bench, затем точное распределение
   по децилям по алгоритму эталона.
3. Согласовать два отображаемых режима с фактически исполняемыми режимами
   эталона. All-or-nothing нельзя выдавать за его пропорциональный режим.
4. Сохранить независимость Str% от режима торговли; принимать изменение
   только при нулевых различиях классификаций и совпадении Str% всех шести пакетов.
5. Отдельно сверить полный Profit по датам и исполнениям сделок, включая
   начало расчёта и учёт фактически открытых позиций.
